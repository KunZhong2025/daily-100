# /daily — 今天的文章

用户提供的题目：**$ARGUMENTS**

## 你要做的事

### 第一步：确定今天写什么

- **有题目** → 直接进入第二步。如果题目太宽泛（比如「聊聊 AI」），先用一句话给出你理解的具体切口，问用户认不认，再往下走
- **没题目** → 读 `docs/topic-bank.md`，从「待写」里挑 3 个还没划掉的，每个用一句话说明为什么今天适合写它，让用户选

选题优先级：**用户今天真实卡住的事 > 选题库里有第一手经验的 > 其他**。

### 第二步：建文章

先确认题目，再执行：

```bash
node scripts/new-post.mjs "<题目>" [--tags 标签1,标签2]
```

日期用默认的今天，不要传 `--date`，除非用户明确说要补写某天。

### 第三步：补 frontmatter

读刚生成的 `index.md`，把 `summary` 填上（一句 40 字以内的话，说清这篇给读者什么），`tags` 按内容给 2-3 个。

### 第四步：出大纲

在 `index.md` 里把模板的各节标题改成贴合今天这篇的具体标题（不要留「第一步」「第二步」这种占位），然后给出：

1. **这篇的核心论点是什么** —— 一句话
2. **你打算怎么组织** —— 各节写什么，对应模板的哪一节
3. **需要用户自己补的地方** —— 明确列出来，比如「花了多少钱」「具体报错原文」「当时的感受」。这些你写不了，标成 `<!-- TODO: ... -->`
4. **你能帮上忙的部分** —— 比如查某个命令的最新用法、补技术细节、验证配置是否还有效

### 第五步：确认

把上面四项摆给用户，问一句「这样切可以吗」，**等确认再往下写**。

## 铁律

- **不要编造用户的经历。** 花费、感受、踩坑过程、具体报错 —— 这些只有用户知道。写成 `<!-- TODO -->` 比编一个好
- **不要一上来就写全文。** 先定角度和大纲。角度错了，写得越多白费越多
- **教程类必须有「我踩到的坑」这一节。** 没有坑的教程等于没写，主动问用户卡在哪了
- 文章长度目标 1500–3000 字，写之前就心里有数

## 写完之后

提醒用户：

```bash
node scripts/md2wechat.mjs posts/<年>/<日期>-<slug> --open
```

看排版效果。确认没问题再把 `index.md` 里的 `status` 改成 `done`，然后打 `/wrap` 收尾。
