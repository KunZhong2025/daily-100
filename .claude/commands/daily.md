# /daily — 今天的文章

用户提供的题目：**$ARGUMENTS**

## 你要做的事

### 第一步：确定今天写什么

- **有题目** → 直接进入第二步。如果题目太宽泛（比如「聊聊 AI」），先用一句话给出你理解的具体切口，问用户认不认，再往下走
- **没题目** → 读 `docs/topic-bank.md`，从「待写」里挑 3 个还没划掉的，每个用一句话说明为什么今天适合写它，让用户选

选题优先级：**用户今天真实卡住的事 > 选题库里有第一手经验的 > 其他**。

### 第二步：建文章

先根据题目和素材判断文章类型与系列；信息足够就直接采用，无法判断时再请用户选择。建文时传入分类，以便套用对应的起始大纲：

```bash
node scripts/new-post.mjs "<题目>" --category "绘本讲解" --series "红火箭" --tags 标签1,标签2
```

分类按文章实际内容替换；没有系列就省略 `--series`。支持「Claude学习」「绘本讲解」「儿歌」「编程与项目」；自定义分类或不指定分类时使用通用模板。

日期用默认的今天，不要传 `--date`，除非用户明确说要补写某天。

### 第三步：补 frontmatter

读刚生成的 `index.md`，把 `summary` 填上（一句 40 字以内的话，说清这篇给读者什么），`tags` 按内容给 2-3 个。按内容手动补充 `category`，建议选「Claude学习」「绘本讲解」「儿歌」「编程与项目」之一，也可以按需新增；属于系列时用自由文本填写 `series`，否则省略。旧文章缺少这些字段也有效，不必回填。

### 第四步：出大纲

在 `index.md` 里把模板的各节标题改成贴合今天这篇的具体标题（不要留「第一步」「第二步」这种占位），然后给出：

1. **这篇的核心论点是什么** —— 一句话
2. **你打算怎么组织** —— 各节写什么，对应模板的哪一节
3. **需要用户自己补的地方** —— 明确列出来，比如「花了多少钱」「具体报错原文」「当时的感受」。这些你写不了，标成 `<!-- TODO: ... -->`
4. **你能帮上忙的部分** —— 比如查某个命令的最新用法、补技术细节、验证配置是否还有效

按内容选择重点：Claude学习写真实学习过程、操作和收获；绘本讲解重原文、讲读和生词；儿歌重歌词、含义和亲子使用场景；编程与项目重问题、实现和实际结果。其他类型按内容确定重点，不强套结构。亲子英语教单词逐词标音标和中文谐音，句子里的新词也要补，区分美国家庭常用口语和场景词；原文与歌词以用户提供或可核实的材料为准。

### 第五步：确认

把上面四项摆给用户，问一句「这样切可以吗」，**等确认再往下写**。

## 铁律

- **不要编造用户的经历。** 花费、感受、踩坑过程、具体报错 —— 这些只有用户知道。写成 `<!-- TODO -->` 比编一个好
- **不要一上来就写全文。** 先定角度和大纲。角度错了，写得越多白费越多
- **教程类必须有「我踩到的坑」这一节。** 没有坑的教程等于没写，主动问用户卡在哪了
- 文章长度目标 1500–3000 字，写之前就心里有数

## 写完之后

**配图按篇选择。** 根据内容和用户意愿决定是否配图；需要配图时，正文定稿后打 `/illustrate`，默认生成 1 张封面。英语练习、亲子绘本与单词学习文章保持简洁，默认只生成封面；正文卡片仅在用户明确要求时添加。不配图时直接继续排版。

然后：

```bash
node scripts/md2wechat.mjs posts/<年>/<日期>-<slug> --open
```

看排版效果（卡片图会提示公众号后台要手动重传）。确认没问题再把 `index.md` 里的 `status` 改成 `done`，然后打 `/wrap` 收尾。
