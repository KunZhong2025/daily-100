## 我为什么要做这件事

想用 Claude Code 这个念头，在我脑子里转了大概有两个月。

不是没用过。一直在用网页版，写代码、问问题、改文案，都挺顺手。但网页版和 Claude Code 是两个东西 —— 网页版是「我问你答」，Claude Code 是「我指个方向，你自己去改我的项目」。

真正让我决定动手的，是我想清楚了一件事：**我要的不只是 Claude Code 那个壳，我要的是它背后的大模型。**

Claude Code 的价值一半在 harness —— 它怎么规划任务、怎么读文件、怎么调工具、怎么在出错之后自己回滚重来。另一半，而且对实际输出质量影响更大的那一半，在背后的模型。同一个 prompt，Sonnet 和 Opus 给出的方案差距是肉眼可见的：Opus 更倾向于给出重构后的结构，Sonnet 更倾向于在现有结构上打补丁。

## 动手之前

先把预期写在这儿，省得你照着做完发现不是你想的那样。

**这不是「白嫖」，是「先小额试水」。** 中转站的成本优势来自批量采购和区域差价，不是因为它免费。你要花钱，只是花得少一点、灵活一点。

**风险要提前知道：**

| 风险 | 具体是什么 |
| --- | --- |
| 数据经过第三方 | 你的代码和 prompt 会经过中转站的服务器，不再只属于你和 Anthropic。**公司代码、密钥、客户数据，别往中转站上发** |
| 稳定性 | 高峰期可能变慢、超时、偶发 5xx。它不是官方 SLA |
| 模型可能被替换 | 便宜的「Claude 通道」有可能是别的模型在冒充。要验证 |
| 账号合规 | 官方服务条款对这类转发路径的态度你需要自己确认 |

**你需要准备好：**

- Windows 10 或 11（我在 Windows 11 Pro 上做的）
- Node.js —— 建议 20 以上，我的环境是 Node 24.14
- Git —— 装 Git Bash，Claude Code 在 Windows 上很多操作依赖它
- 一个中转站账号，以及一笔预算。**建议第一笔控制在几十块钱以内**，跑通了再追加
- 时间：顺利的话 40 分钟，踩坑的话一个下午

## 具体怎么做

### 第一步：装 Claude Code

官方安装脚本有好几种，Windows 上最省事的是 npm：

```bash
npm install -g @anthropic-ai/claude-code
claude --version
```

装完先**不要**急着登录。因为下一步我们要把它的认证方式改掉，你现在登录官方账号，后面还得登出。

如果 Windows 弹 SmartScreen 或者权限警告，用管理员身份开终端重跑一次。

### 第二步：装 cc-switch

这一步是整件事的关键。[cc-switch](https://github.com/farion1231/cc-switch) 是一个开源的桌面应用，专门干一件事：**管理并一键切换 Claude Code 的供应商配置。**

它解决的痛点很具体。Claude Code 换供应商，本质上是改 `~/.claude/settings.json` 里的三个字段：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://你的中转站地址",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的key",
    "ANTHROPIC_MODEL": "claude-opus-4-6"
  }
}
```

手动改当然可以。但如果你要在「官方 / 中转站 A / 中转站 B / 国产模型」之间来回切，每次手改 JSON 就是在赌自己不手抖 —— 少一个逗号，Claude Code 直接连不上，而且报错信息不会告诉你哪错了。

cc-switch 把这件事变成了点一个按钮。它还顺手做了备份、配置导入导出、端点测速。

**⚠️ 先记这一条：cc-switch 是完全免费开源的，只从 GitHub Releases 下载。** 任何向你收费、要你充值、或者索要登录凭据的「cc-switch 官网」都是假冒的。项目作者专门在 release notes 里写了这个警告。

Windows 安装，去项目的 Releases 页面下载 `.msi` 安装包，或者 `-Windows-Portable.zip` 免安装版解压即用。

界面是中文的，装完直接能看懂。

### 第三步：添加中转站作为供应商

在 cc-switch 里点右上角的 `+` 添加供应商，需要填三样东西：

| 字段 | 填什么 |
| --- | --- |
| 名称 | 自定义，比如 `relay-a`，方便你以后认 |
| 请求地址 | 中转站给你的 **Anthropic 协议** 地址 |
| API Key | 中转站后台生成的 key |

**两个容易错的地方：**

1. **地址要用 Anthropic 端点，不是 OpenAI 端点。** Claude Code 说 Anthropic 协议。很多中转站同时提供 `/v1`（OpenAI 格式）和 `/anthropic`（Anthropic 格式）两个入口，填错了会认证失败或者直接诡异报错
2. **末尾不要多斜杠。** `https://xxx/anthropic` ✅，`https://xxx/anthropic/` ❌

模型那一栏可以留空走默认，也可以指定。指定的话建议填 Opus 系列，理由我在开头说过了。

### 第四步：切换并验证

回到供应商列表，选中刚加的，点启用。cc-switch 会把配置写进 `~/.claude/settings.json`。

**然后关掉当前终端，重新开一个**，运行：

```bash
claude
```

#### 先看一眼配置有没有落盘

这一步比在 Claude Code 里找状态显示更直接：

```bash
cat ~/.claude/settings.json
```

你应该能在 `env` 段里看到 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 两个字段。**没看到就说明 cc-switch 没写成功**，别往下走，先解决这一步。

#### 再确认 shell 里没有残留

配置文件不是最高优先级的。如果你之前手动 `export` 过同名变量，它会盖掉配置文件：

```bash
echo $ANTHROPIC_BASE_URL
echo $ANTHROPIC_AUTH_TOKEN
```

只要有一个有输出，就说明有残留，先 `unset` 掉。

#### 然后用 `/status` 看账号

```
/status
```

⚠️ **这里有个很多人（包括我）会踩的预期偏差**：`/status` 打开的是设置界面的 Status 标签，它显示的是**版本、模型、账号、连通性** —— 它**不显示 Base URL**。所以别去找那一行，找不到的。

要看的是 **account（账号）那一行**：

- 显示你的订阅（Pro / Max）→ **说明没切过去**，请求还在走官方
- 显示用的是 API key / 没有订阅 → 说明已经走你自己的 key 了，也就是中转站在生效

#### 最后做功能验证

配置层面看完了，还得确认它真能干活：

```
帮我看看当前目录下有哪些文件，说说这个项目大概在做什么
```

能正常列出文件并给出合理总结，就成了。

**顺便记一个代价**：从 v2.1.196 起，`ANTHROPIC_BASE_URL` 一旦指向非 `api.anthropic.com` 的主机，**Remote Control 功能会被禁用**，MCP 工具搜索也会默认关掉（要手动设 `ENABLE_TOOL_SEARCH=true` 才能开）。这是走中转站要付的功能性代价，不是 bug。

### 第五步：配 Happy，用手机遥控

这一步不是必须的，但它解决了一个很实际的问题：**Claude Code 跑长任务的时候，你得盯着屏幕。**

[Happy](https://happy.engineering) 是一个开源（MIT）的客户端，有手机 App 也有 Web 端。装完之后，你在电脑上跑会话，手机上能实时看到它在干什么；它需要你确认权限的时候，手机会推通知；你人不在电脑前，也能一句话让它继续。

它不只支持 Claude Code，Codex 也能接 —— 官网标题写的是 Claude Code、Codex 和 Grok 三家。

它的架构很简单，三部分：电脑上跑的 CLI 负责启动和监听 Claude Code，把内容加密后发到中继服务器；手机或浏览器上收下来解密显示；中继服务器只是个搬箱子的，看不到内容。

安装：

```bash
npm install -g happy
```

> 老教程里写的 `happy-coder` 是项目早期的包名，现在停更在 1.1.x。**认准 `happy` 这个包名**，它的 bin 还是叫 `happy`，所以有人两个都装了也不冲突，只是版本会旧。

然后**用 `happy` 代替 `claude` 启动**：

```bash
happy claude
```

启动之后终端里会出来一个二维码，用手机上的 Happy App 扫一下就连上了。

它还有几个值得知道的命令：

```bash
happy auth      # 管理登录状态
happy doctor    # 出问题时的诊断
happy daemon    # 后台服务管理
```

### 坑一：改完配置不生效

Claude Code 是**在启动时**读 `settings.json` 的。已经开着的会话不会重读配置。

所以切完供应商，必须关掉终端重新开一个。如果你在 tmux 或者编辑器内置终端里跑，光 detach / attach 不够，得把进程真的杀掉。

### 坑二：以为配置切了，实际还在走官方

这个坑的根源是**验证方法选错了**。

很多教程（包括我一开始想当然的写法）会说「打开 `/status` 看 Base URL 那一行」。但 `/status` 根本不显示 Base URL —— 它显示的是版本、模型、账号、连通性。你要是拿这个当验证手段，会一直以为自己没切成功，然后开始乱改配置。

正确的验证是两条腿：

```bash
# 一、看配置有没有落盘
cat ~/.claude/settings.json

# 二、看 shell 里有没有残留（残留会盖掉配置）
echo $ANTHROPIC_BASE_URL
```

配置在、shell 干净、`/status` 的账号那行不显示你的订阅 —— 三条对上，才是真的切过去了。

### 坑三：`ANTHROPIC_API_KEY` 和 `ANTHROPIC_AUTH_TOKEN` 不是一回事

这两个变量长得像，用途完全不同：

- `ANTHROPIC_API_KEY` → 作为 **`X-Api-Key`** 头发出
- `ANTHROPIC_AUTH_TOKEN` → 作为 **`Authorization`** 头发出

中转站绝大多数是认 `Authorization` 头的，也就是要 `ANTHROPIC_AUTH_TOKEN`。填错成 `API_KEY`，表现是一路 401 或者 403，而且报错信息不会告诉你「你该换另一个变量名」。

cc-switch 帮你填的是对的，但如果你后来手动改配置文件，很容易在这儿翻车。

### 坑四：中转站临时抽风

写这篇的时候我正在跑一个后台任务，中途拿到这么一条报错：

```
API Error: 503 No available channel for model xxx under group xxx (distributor)
```

翻译过来就是：**这个模型分组下面，当前没有可用的通道。**

这不是配错了，是中转站侧的容量问题 —— 某个模型组在高峰期被占用完了。它通常会自己恢复，重试几次就好。

但它说明一件事：**你的开发流程依赖的是第三方的容量，而不是官方容量。** 这就是前面那张风险表里「稳定性」一行的实证。真遇到赶进度的时候，你得知道临时切回官方订阅或者换个分组是备选方案。

## 小结

三条我现在的判断：

1. **cc-switch 值得装**，但它值得装的理由不是「能省订阅费」，是「能在多个供应商之间无痛切换」。如果你只用一个供应商，直接改 `settings.json` 更快，别为了省事装个桌面应用
2. **中转站适合验证，不适合长期承载。** 拿它试水、跑非敏感项目没问题；一旦你确认了自己的使用习惯，值得重新算一遍官方订阅的账
3. **先用起来，比配置得完美更重要。** 我在配置上纠结的时间，如果拿来实际用，早就把这点钱挣回来了
