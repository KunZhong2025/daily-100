先说结论：**不要让提出方案的 AI，成为方案唯一的审查者。**

平时用 Claude Code 和 Codex CLI 开发 CaseStruct 和 CodeLens 时，经常有一种看似良好但很危险的感觉：我和 Agent 聊得越久，双方越发默契，方案推演得丝丝入扣。

但问题在于：**Agent 可能只是越来越理解我的想法，却没有真正质疑我的想法。**

今天 Google 开源的一个项目给了我很直接的启发——**Elephant-Goldfish Model（EGM）**。它不是什么新基座大模型，而是一套对抗上下文污染与思维回音壁的 Agent 工作流程。

## 我和 Agent 配合时的盲区

这种「回音壁」陷阱在日常开发中太常见了。

比如在设计 CaseStruct 的多人协作功能时，我和 Agent 在同一个会话里反复推敲流程：任务怎么认领、数据怎么锁定、状态怎么提交。聊了几十轮，双方达成一致，Agent 给出了一份看似详尽的设计，接着直接开始写代码。

但真正落到实处才发现，致命的边界条件全漏了：

- 如果客户端网络突然中断，持有的锁如何超时释放与恢复？
- 如果多个人在几乎同一时刻提交，冲突仲裁和版本回滚怎么做？

回过头想，为什么讨论了那么久都没发现？

因为同一个 Agent 伴随我走过了整个决策过程。在漫长的上下文里，它已经默认了我所有的前提假设，它理解我的偏好，但也完美继承了我的认知盲点。

**写方案的人（或 AI）审查自己的方案，看到的永远是符合预期的主干，而不是潜藏在暗处的暗礁。**

## Elephant-Goldfish 模式：大象记事，金鱼挑刺

Google 在 GitHub 上以 Apache 2.0 许可证开源了 `elephant-goldfish-model`。它的核心思路非常纯粹，把开发切分为三个角色：

### 1. Elephant（大象）
大象拥有极好的记忆。在长上下文会话中，它完整保留项目背景、历史决策和需求细节，负责跟开发者反复沟通并起草规范文档（Spec）。**在这个阶段，大象绝对不写一行实际代码。**

### 2. Goldfish（金鱼）
金鱼只有「7 秒记忆」，也就是**零历史上下文（Zero-Context）**。它完全不了解此前几十轮密密麻麻的讨论，只阅读大象最终交出的设计文档和必要的系统接口。以挑剔的「局外人」视角，专门寻找遗漏的边界条件、逻辑冲突和不合理假设。

### 3. Human（开发者）
开发者作为裁判，评估金鱼提出的审查意见，批准最终设计后，再进入编码阶段。

同时，它还支持在写完代码后，检查实际代码是否偏离了最初的设计规范。官方也明确提醒：它不能替代真实测试，也不能替代人类的工程判断。

但这套机制点透了一个本质问题：**多 Agent 的价值不只是分工协作，更在于通过上下文隔离阻断偏见传递。**

## 不装插件，今天就能落地的「最小动作」

看到新工具，很多人习惯第一件事就是去装插件、改配置。其实完全没必要。

EGM 最值钱的是它的思想。在现有的 Claude Code 或 Codex CLI 中，不需要装任何新插件，今天就能做一次最小尝试。

挑一个手头尚未实现的功能（比如 CaseStruct 的某个协作子模块），按下面两步走：

### 第一步：大象出方案（严禁动手写代码）

在当前上下文会话里，让 Agent 深入理解现有代码并产出简短方案：

```text
请先阅读项目现有设计文档和相关代码，不要修改任何文件。
针对即将开发的功能，整理一份简短的设计方案。
```

### 第二步：金鱼独立审查（切忌同一会话内角色扮演）

**关键前提：当前工具必须支持真正独立的子会话（Sub-agent）或开启全新窗口。**

绝对不能在同一个会话里说「你假装成另一个专家来挑刺」，只要上下文带着之前的几十轮讨论，角色扮演依然逃不出思维定势。

开启全新独立会话，只提供设计方案和必要的背景材料，输入这段提示词：

```text
你是一个独立的架构审查 Agent。
请只根据这份设计方案和必要的接口材料，寻找遗漏的边界条件、错误假设和潜在风险。
最终只向我报告最重要的三个问题，等待我决定是否修改方案。
```

拿到这三个问题后，由你来拍板：是修改设计，还是确认无误后直接开始编码。

如果这种极简的手动隔离审查确实能帮你揪出盲点，未来再考虑引入更复杂的自动化流程也不迟。

## 我的思考：写代码之前，先少犯不该犯的错

这套思路与我一直想搭建的「一个助理协调多个专家」工作方式非常契合。

过去评估 AI Coding 工具，大家习惯看它能补全多少行、生成代码有多快。但随着模型能力越来越强，生成代码的边际成本已经降到极低，反而是修 Bug、返工和排查架构硬伤的成本在成倍上升。

**AI Coding 的下一步，不一定是让 Agent 狂写更多代码，而是让它在写代码之前，帮我们发现更多不该犯的错误。**
